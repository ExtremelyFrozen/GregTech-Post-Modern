# 配方执行

`RecipeLogic` 按机器 Tick 驱动配方。开始、每刻处理和结束分别传入对应的 `ContentListMap`，由 `RecipeRunner` 与处理器执行输入输出。


## 处理器契约

`RecipeHandlerList` 汇集具有同一处理器组的能力处理器。每个处理器支持相应 `IO` 方向，接受该能力尚未处理的内容列表，并返回余量。空余量表示能力的内容已全部处理。`RecipeHandlerList` 从结果映射中移除已经清空的能力键。存在余量时，下一个可用处理器继续处理。

处理器支持模拟与执行。模拟检查匹配、容量和消耗空间，执行才更新实际库存、流体或能量。输入余量会使当前组合失败。输出余量按机器的虚空设定判断能否丢弃。

独立模式的输入总线先按组检查，`BYPASS_DISTINCT` 提供可与独立总线合用的能力。染色处理器按颜色选择，未染色处理器可参与颜色组。普通输出还会按处理器组优先级安排分配。


## 一条配方的生命周期

1. `checkMatchedRecipeAvailable` 应用 `fullModifyRecipe`，检查机器条件和各能力的输入输出。
2. `setupRecipe` 运行机器的 `beforeWorking` 钩子并消耗一次性输入。成功后设置持续时间和进度。
3. `handleRecipeWorking` 检查每刻条件，模拟并执行每刻输入与输出。处理成功后运行机器的 `onWorking` 钩子并更新进度。
4. `onRecipeFinish` 运行机器的 `afterWorking` 钩子并处理一次性输出。输出受阻时进入等待，收到足够输出空间后继续完成。有后续可运行配方时立即准备下一轮。

`ActionResult` 携带失败原因，以及有对应能力时的能力和 I/O 方向。每刻能量输入失败会触发退避。多方块反复供电不足时可能进入暂停状态，机器控制覆板可通过其防断电设置干预该路径。

装配线用有序处理器按总线顺序消耗输入。蒸馏塔按层处理普通蒸馏塔配方的流体，蒸馏室配方的流体送到首个有效输出仓。蒸馏室配方只有物品产物时，流体输出检查直接通过。
