# GregTech Post Modern 1.21.1 迁移指南

GTPM 运行在 Minecraft 1.21.1 和 NeoForge 上，机器、覆板及配方界面使用 LDLib2。内置资源使用 `gtpm` 命名空间，Java 根包为 `com.gregtechceu.gtceu`，命令根为 `/gtceu`。


## 整合包与附属模组

内置 KubeJS 集成已移除。按自定义内容选择数据包、资源包或附属模组入口。

| 要迁移的内容 | 当前入口 |
| --- | --- |
| 添加、替换、移除机器配方 | 在 `data/<namespace>/recipe/` 提供 JSON，或实现 `IGTAddon.addRecipes` 与 `removeRecipes`。 [配方数据包](../Recipes/Adding-and-Removing-Recipes.md) |
| 配方条件与修改器 | JSON 通过 `recipeConditions` 指定条件。附属模组通过机器的 `recipeModifiers` 应用运行时修改器。 [条件](../Recipes/Recipe-Conditions.md) · [修改器](../Recipes/Custom-Recipe-Modifiers.md) |
| 材料、元件和机器注册 | 在附属模组中使用对应注册表、`Material.Builder` 与自己的 `GTRegistrate`。 [材料注册](../Materials-and-Elements/01-Material-Creation.md) · [机器注册](../Other-Topics/Custom-Machines.md) |
| 普通矿脉、基岩矿脉与流体矿脉 | 数据包使用 `data/<namespace>/gtpm/ore_vein/`、`bedrock_ore/` 或 `bedrock_fluid/`。 [矿脉数据包](../Ore-Generation/index.md) |
| 多方块布局与预览 | 模组资源使用 `multiblock/<namespace>/json/` 或 `binary/`。Java 或 Kotlin 通过 `pattern(name, factory)` 挂接。 [结构格式](../Other-Topics/Multiblock-Structures.md) |
| 机器与配方界面 | 用 `/gtceu ui_editor` 为目标生成 LDLib2 XML。资源包按 `assets/<namespace>/ui/` 下的目标路径提供模板。 [界面编辑器](../Other-Topics/LDLib-UI-Editor.md) |

覆盖内置内容时保留要覆盖的资源 ID。添加附属模组或整合包自己的新资源时使用所属命名空间。替换迁移前的资源引用时，按当前注册表核对完整 ID。


## 配方、能量与算力 API

| 旧代码入口 | 迁移方式 |
| --- | --- |
| 数据加载或配方查看器中的运行时 `GTRecipe` | 使用 `GTRecipeDefinition` 读取定义。需要匹配、修改或执行时用 `toRuntime()` 取得 `GTRecipe`。 |
| `EnergyStack` | 配方 `eu` 内容改用 `Long` 总量。普通 I/O 表示 EU，每刻 I/O 表示 EU/t。`GTRecipeBuilder` 的双参数方法用电压乘以电流，配方等级单独保存为 `tier`。 |
| `RecipeAmperageEnergyContainer` | 在机器侧用能源容器暴露能量，通过 `getTierVoltage()` 和 `getOverclockVoltage()` 分别读取等级电压与超频电压。 |
| `BlockStateRecipeCapability` | 检查世界方块时使用适合的 `RecipeCondition` 或机器逻辑，需要自定义可消费资源时注册配方能力。 |
| `ChargerMachine` | 使用 `new BatteryBufferMachine(info, tier, inventorySize, BatteryBufferMachine.AMPS_PER_BATTERY_CHARGER, 0)`。 |
| 请求光学算力的机器代码 | 使用 `ComputationPort`、`ComputationProducer`、`ComputationConsumer` 与对应 trait。研究站从网络取得 CWU，装配线通过数据访问接口查询研究 ID。 |

## 保存、同步与交互

在自定义存档读取与 GameTest 结构模板中使用 `gtpm_sync_data`，字段值用当前 Codec 编码。需要保存在掉落机器上的字段使用 `@ItemSave`，持有物品的状态通过 `ItemSyncHolder` 存入 `gtpm:item_data`。机器记忆卡通过独立配置组件传递 `SyncFieldData`。

把直接使用旧 LDLib 同步、旧字段转换器或界面专用动作包的调用迁到字段注解与 Codec。使用 `@SyncBoth` 表示可编辑设置，使用方法 RPC 表示一次性操作。 [同步迁移](../../Development/Data-Sync-System/Migrating-From-LDLib-SyncData.md) · [RPC](../../Development/Data-Sync-System/RPC.md)

当前分支使用网络协议 `26.11.3`。联机时客户端与服务端使用协议匹配的 GTPM 版本。旧终端的绑定和逐机选项由当前终端的持久字段替代，进入游戏后重新绑定主机并设置搭建选项。 [终端玩法](../../Gameplay/Multiblocks.md)


## 开发环境

构建使用 Java 21 和 Gradle Wrapper 9.9.1。当前分支的开发运行配置使用 NeoForge 21.1.265 与 LDLib2 2.2.44。测试配方和夹具通过独立的 GameTest 入口加载。 [开发运行环境](../../Development/General-Topics/Development-Environment.md)
